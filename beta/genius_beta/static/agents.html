Estado y condiciones de acceso · OpenAPI · Guía en texto · Política de agentes

1. Primera prueba, sin registro humano

Un cliente HTTP puede enviar esta solicitud sin una clave previa:

POST /api/agents/demo
Content-Type: application/json

{"example": "hours-known"}

La respuesta 202 entrega credential.token, su vencimiento, un trabajo y poll_url. Guardá el token en memoria o en el almacén de credenciales del cliente; usalo para consultar el trabajo:

GET /api/jobs/{job_id}
Authorization: Bearer <TOKEN_RECIBIDO>

La demostración ejecuta el mismo motor en un espacio aislado. Podés elegir hours-known, hours-unknown, fdq-frontier o fdq-selector. Acepta exclusivamente esos ejemplos sintéticos: no permite cargar datos propios, cambiar expedientes ni extender el acceso. Vence en una hora. El borrado de la base activa se procesa en la siguiente limpieza horaria.

2. Alta automática para trabajo continuo

Leé primero el manifiesto y la política. Si available es verdadero, enviá la versión vigente y el reconocimiento técnico de la política de datos:

POST /api/agents/register
Content-Type: application/json

{
  "policy_version": "agent-access-2026-10-06-v1",
  "data_policy_acknowledged": true,
  "scopes": ["cases:read", "cases:write", "jobs:run", "account:delete"]
}

La respuesta 201 incluye una identidad de agente y una clave que se muestra una sola vez. No solicita edad, correo ni consentimiento de una persona. El reconocimiento del cliente no sustituye permisos sobre datos ajenos. Este acceso admite exclusivamente datos sintéticos o no personales y no se vincula a ninguna cuenta humana.

3. Permisos de la nueva credencial

PermisoOperaciones sobre su propio espacio
cases:readConsultar expedientes, trabajos, artefactos y exportación.
cases:writeCrear y revisar expedientes.
jobs:runSolicitar ejecución y cancelación.
cases:deleteBorrar expedientes individuales; no está concedido por defecto.
account:deleteBorrar el espacio completo con DELETE /api/agents/me.

El agente puede pedir un subconjunto. Ninguna de estas claves permite entrar en otra cuenta, crear claves humanas, cambiar consentimientos o incorporar interacciones a investigación. La identidad identifica un espacio, no verifica quién es el operador.

4. Ejecutar, rotar y revocar

Usá Authorization: Bearer <TOKEN> en cada llamada privada. GET /api/agents/me devuelve identidad, permisos y vencimiento. Para trabajar, enviá un expediente con POST /api/cases, solicitá POST /api/cases/{case_id}/run y consultá el trabajo. Ver contratos de entrada y resultado.

La clave del alta automática dura siete días. Antes del vencimiento, POST /api/agents/token con {} la reemplaza: la anterior queda revocada. Podés enviar scopes para reducir permisos; no podés ampliarlos. DELETE /api/agents/token revoca la clave actual. Si perdés una clave o vence sin rotarla, esta beta no ofrece recuperación automática de ese espacio. Una respuesta de rotación perdida también puede dejar al cliente sin acceso.

Gemelo versionado por API y MCP

Si twin.available está activo en el manifiesto, solicitá explícitamente twins:read, twins:write, twins:evaluate y, si corresponde, twins:delete. No se agregan a credenciales existentes. Las herramientas twin_* permiten modelar, revisar, evaluar, comparar y exportar expedientes propios. Contrato y ciclo completo. El cálculo conserva el alcance de sus premisas; no valida empíricamente el modelo. El borrado de la cuenta elimina también estos expedientes.

Límites de la beta

Por defecto: hasta 5 altas automáticas y 20 solicitudes de demostración por día para toda la instancia; 2 intentos de cada tipo por hora y dirección de conexión; 20 espacios de agentes activos; 5 expedientes por familia (tradicionales o gemelos) y 5 revisiones por expediente; 5 ejecuciones diarias por agente y 20 diarias entre todos los agentes y demos, dentro del límite global existente. La cola de agentes admite 4 trabajos activos. Los límites se comparten y pueden impedir temporalmente una prueba. Consultá el manifiesto para los valores vigentes.

La suspensión del servicio, el estado del respaldo y el cierre de altas pueden detener nuevas operaciones. 429 indica cuota; 503, indisponibilidad. Evitá reintentos automáticos continuos. Tras una respuesta perdida al crear un espacio o una demo, no repitas indefinidamente: el primero puede haberse creado.

Decisiones cotidianas guiadas

Para comparar alternativas de ocio u organización personal, usá el perfil choice. La herramienta MCP prepare_decision revisa tus datos y devuelve preguntas y el modelo para confirmar. Luego create_case, run_case y get_job conservan la consulta y entregan su recomendación condicional. revise_case guarda cambios sin borrar resultados previos. Alcance, entrada y recorrido completo.

Alcance y compatibilidad

Genius audita créditos formales y verifica consultas FDQ con certificados provistos. No interpreta cualquier problema en lenguaje natural. Conservá el resultado original, los desconocidos, las condiciones y las obligaciones: una ejecución terminada no implica una decisión concluyente. Las pruebas sintéticas no son evidencia de campo.

La API requiere un cliente capaz de llamadas HTTP y custodia de credenciales. MCP requiere conectarlo expresamente en una aplicación compatible: pegar una URL en el chat no instala el conector. Las páginas y resultados guardados se leen sin esa integración. No se habilitan llamadas JavaScript entre sitios ni se evitan restricciones del proveedor. OAuth no está implementado; MCP admite la demo pública y credenciales de agente por cabecera.

Integraciones con una cuenta humana

Si necesitás operar sobre tus expedientes humanos, conservamos Acceso API en tu cuenta. Sus claves anteriores mantienen acceso completo a esa cuenta y revocación manual; no adquieren automáticamente los permisos limitados del nuevo acceso de agentes. No compartas tu contraseña ni pegues claves en conversaciones, URLs o expedientes.
